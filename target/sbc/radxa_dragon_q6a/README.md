# AR0234 на Radxa Dragon Q6A

**Статус: разработка; переходник, сборка драйвера и захват не проверены.**
Q6A — целевая плата для цветного DECXIN-3478V1 с объективом 200°.
Установки, которая уже получает кадр с этой камеры, в пакете нет.

## Подключение

| Сторона | Интерфейс | Следствие |
| --- | --- | --- |
| DECXIN | 22 контакта, 0,5 мм, заявлены четыре линии CSI | [Распиновка камеры](../../../docs/reference/pinout.md) задаёт собственную нумерацию |
| Q6A J14 / CAM1 | 31 контакт, 0,3 мм, четыре линии CSI | Нужен отдельный переходник 22→31 с проверенной схемой |
| Q6A J16 / CAM2, J7 / CAM3 | 15 контактов, 1 мм, две линии CSI | Требуются переходник и рабочий двухлинейный режим сенсора; пределы частоты проверяются отдельно |

По [Radxa CSI](https://docs.radxa.com/en/dragon/q6a/hardware-use/mipi-csi)
J16/J7 имеют распиновку Raspberry Pi. Это не делает DECXIN прямым подключением.
На схеме Q6A V1.21, страница PDF 32 (лист 34/37), подтяжки J14 I2C и
CAM0_POWER_EN — 1,8 В; J16/J7 имеют преобразователи 1,8↔3,3 В.
См. [справочник Q6A](https://github.com/pOmelchenko/radxa_dragon_q6a/blob/main/docs/reference/hardware.md#камерные-разъёмы).

Переходник должен явно сопоставлять питание, все земли, I2C, CSI D0–D3,
тактовую пару и ориентацию обоих концов. DECXIN 1 = 3,3 В, а RPi22 1 = GND.
Контакты DECXIN 5/6 обозначены NC. Нельзя назначать им reset/XCLK по аналогии.
Источник XCLK, напряжение I2C и схема включения модуля требуют уточнения.
J2 TRG/STRB остаётся неподключённым до получения электрического контракта.

## Порядок разработки

1. Зафиксировать маркировку своего модуля, ревизию Q6A и прозвоненную схему
   переходника. Проверить напряжения и питание до подключения сенсора.
2. Подготовить ОС по [репозиторию Q6A](https://github.com/pOmelchenko/radxa_dragon_q6a).
   Зафиксировать ядро, BIOS, DT и исходники именно установленного BSP.
3. Использовать [кандидат AR0234](../../../docs/reference/drivers.md) как основу
   сенсорного драйвера. Согласовать I2C/chip ID, регуляторы, reset, EXTCLK
   и power sequencing с DECXIN. Pi overlay на Q6A не применяется.
4. Связать sensor endpoints с реальным CSI/CAMSS маршрутом Q6A; согласовать
   число линий, link frequency и формат на всех pads. Установить один
   непрерывный умеренный режим до проверки 120 кадр/с и внешнего запуска.
5. Получить исходный кадр; проверить размер, Bayer, разрядность, экспозицию,
   gain и обработку цвета. Затем измерить длительный поток и ошибки CSI.
6. Откалибровать объектив 200° и отдельно проверить TRG/STRB, принимаемые
   импульсы и временные метки экспозиции.

В [перечне Radxa](https://docs.radxa.com/en/dragon/q6a/hardware-use/mipi-csi)
AR0234 не названа среди совместимых камер. Это не устанавливает невозможность
портирования; готового рабочего сочетания BSP/DECXIN в пакете нет.

## Диагностика подготовленного Linux

После установки `v4l-utils` на целевую Q6A:

```sh
uname -r
cat /etc/os-release
v4l2-ctl --list-devices
media-ctl -d /dev/media0 -p
```

`/dev/media0` здесь пример: нужно выбрать устройство CAMSS из перечисления.
Появление sensor entity — только этап проверки. Настройка links, форматов
и захвата зависит от полученного графа; готовой команды STREAMON для этой
конфигурации пока нет. См. [контракт V4L2 media/subdev](https://www.kernel.org/doc/html/latest/userspace-api/media/v4l/dev-subdev.html).

Результат оформляется по [критериям пакета](../../../docs/development/README.md).
Код и патчи этой связки добавляются в этот каталог, зависимости — локально
в `vendor/`, сборки — в `build/`, вывод — в `runs/`.
